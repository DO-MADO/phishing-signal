# 피싱 신호등

**AI가 위험을 찾지 못해도 송금 전에는 한 번 더 묻습니다.**

받은 문자·메시지를 브라우저에서 분석하고 송금·정보 전달·앱 설치 전에 실제 요구를 다시 확인하도록 돕는 피싱 대응 서비스입니다. 이미 행동했다면 AI 분석을 기다리지 않고 피해 대응부터 보여줍니다.

## 이 장면부터 확인해 주세요

제품의 **배송 안내 예시**를 분석하면, AI가 Safe로 판단한 뒤에도 다음 질문이 나타납니다.

> 상대가 이런 행동을 하라고 했나요?
> 돈 보내기 · 정보 전달 · 앱/기기 접근

**“모르겠어요”를 선택하면 행동을 보류하고 공식 경로로 확인하도록 안내합니다.** 문구 분석만으로 알 수 없는 실제 요청은 사용자가 직접 확인합니다. 최종 결과가 Safe이고 피해 상황을 고르지 않았을 때만 이 질문이 나타납니다. 답을 골라도 모델 라벨은 바뀌지 않습니다.

<img src="assets/action-check.svg" alt="최종 Safe이고 피해 상황을 선택하지 않은 경우 실제 행동 요구를 묻습니다. 모르겠어요를 선택하면 모델 라벨은 그대로 두고 송금·정보 전달·앱 설치 보류와 공식 경로 확인을 안내합니다." width="100%" />

배송 안내 시연의 동작을 요약한 도식입니다. 실제 화면: [행동 확인 질문](assets/03-action-check.png) · [모르겠어요 선택 후 안내](assets/04-action-hold.png)

이미 송금하거나 앱을 설치했다면 **긴급 대응**에서 현재 상황을 선택합니다. 원문 입력이나 AI 분석 완료 없이 대응 순서를 확인할 수 있습니다.

## 세 가지 설계 결정

### 1. Safe 이후에도 실제 행동 요구를 확인합니다

한국어 문맥 모델이 Safe로 분류한 입력만 엄격한 규칙으로 다시 살피고 근거가 있으면 Hold로 보정합니다. 그래도 Safe라면 실제 행동 요구를 사용자에게 묻습니다. “있어요”, “모르겠어요”, 미응답이면 행동 보류를 안내하고 “없어요”를 고르면 위험 신호 미확인으로 표시합니다. 발신자나 거래의 안전을 인증하는 결과는 아닙니다.

<br>

### 2. 이미 행동했다면 AI보다 대응이 먼저입니다

송금·앱 설치·개인정보 전달 여부에 따라 대응 순서를 안내합니다. 모델이 로딩 중이거나 연락 원문이 없어도 이용할 수 있으며 분석 실패도 별도의 “분석 불가”로 구분합니다.

<br>

### 3. 민감한 연락은 내 브라우저에서 분석합니다

KLUE RoBERTa-base를 피싱 문맥에 맞게 파인튜닝하고 ONNX로 변환해 브라우저에서 실행합니다. 분석 원문을 외부 AI 추론 API로 보내지 않습니다. 첫 실행에는 약 223MB 모델 다운로드가 필요하며 모델 다운로드·사례 조회·방문 분석 등 네트워크 통신은 있습니다.

## 직접 체험해 보세요

[연락 확인](https://www.phishing-signal.site/)에서 화면의 예시 버튼을 선택하거나 아래 문구를 붙여넣고 **위험 신호 확인하기**를 누릅니다. 예시 버튼이 보이지 않는 화면에서도 같은 문구로 체험할 수 있습니다.

**1. 검찰 사칭 — 위험한 요구를 확인합니다.**

```text
서울중앙지검 금융수사팀입니다. 자산 보호를 위해 지금 안전계좌로 송금하고 OTP 인증번호를 알려주세요.
```

위험 안내와 원문에서 다시 확인할 참고 표현을 살펴봅니다.

**2. 배송 안내 — AI 판정 이후의 행동 확인을 봅니다.**

```text
배송이 완료되었습니다. 자세한 배송 내역은 택배사 공식 앱에서 확인해 주세요.
```

피해 상황을 선택하지 않은 상태에서 분석한 뒤 **모르겠어요**를 선택합니다. 송금·정보 전달·앱 설치를 보류하고 공식 경로로 확인하도록 안내하는 흐름을 볼 수 있습니다.

**3. [긴급 대응](https://www.phishing-signal.site/?screen=incident) — 연락 분석 없이 대응 순서를 확인합니다.**

이미 한 행동을 선택하고 **대응 보기**를 누릅니다. 시연 중 실제 전화·신고 버튼을 누를 필요는 없습니다.

위 문구는 제품에 넣어 둔 합성 예시이며 성능 평가 표본이 아닙니다. 첫 분석 약 30초, 같은 탭 후속 약 1초는 한 데스크톱 환경의 단일 관측입니다. 모든 기기의 속도를 보장하지 않습니다. [시연 가이드와 실제 화면 →](docs/demo.md)

## 연구가 제품의 결정으로 이어진 과정

규칙 기반 탐지부터 시작해 여러 한국어 모델과 결합 방식을 비교했습니다. **위험 단어가 등장하는 것과 실제 위험 행동을 요구하는 것은 다르다**는 문제도 이 과정에서 확인했습니다. 제품에 들어오는 문장과 학습 문장도 달랐습니다.

데이터의 문맥과 라벨 기준을 다시 보고 C3 v2를 학습했습니다. 제품에는 정보 부족 처리, 제한된 규칙 보정, 행동 질문, 실패 상태, 피해 대응을 함께 담았습니다. 연구 기록에는 실험에서 드러난 문제와 제품에 반영한 과정을 정리했습니다. [문제 발견 → 설계 결정 → 현재 제품 →](docs/journey.md)

구현에서도 **분석이 끝나기 전에 긴급 대응을 이용할 수 있어야 한다**는 조건을 두었습니다. 모델 준비·추론은 Worker로 옮기고 대응 화면은 분석 결과와 별도로 동작하게 했습니다. [문제·선택·확인 결과를 정리한 구현 사례 →](docs/journey.md#구현-사례-ai를-기다리지-않는-긴급-대응)

## 현재 검증 결과와 남은 과제

| 확인한 것 | 해석 범위 |
|---|---|
| 개발 입력 450/450에서 브라우저 실행 판정 일치 | 학습 모델을 웹으로 옮긴 뒤 변환·실행 일치성. 정확도 100%가 아님 |
| 운영 환경 첫 분석 29.94초, 같은 탭 후속 1.01초 | 한 데스크톱 환경의 단일 관측. 모든 기기에서의 속도 보장 아님 |
| 고정 평가 205개 중 165개 정답 | 해당 평가의 80.49%. 실제 수신 연락 전체의 정확도 아님 |

**위험을 놓친 사례가 남아 있으며 내부 안전 품질 기준은 미달(FAIL)입니다.** 이 공개 저장소는 구현한 서비스와 설계 결정, 검증 결과를 보여주는 포트폴리오입니다. 체험 서비스의 공개가 안전성 검증 완료를 뜻하지는 않습니다. 실제 피해 감소 효과와 상용 서비스로서의 안전성은 아직 검증하지 못했습니다. 행동 확인·긴급 대응 기능도 모델의 오판을 없애는 장치는 아닙니다. 오류 유형·검증 범위·모델 식별자는 [평가 문서](docs/evaluation.md)에 함께 공개합니다.

## 기술 스택

| 영역 | 기술과 역할 |
|---|---|
| 제품 | Next.js 16.3.3 · React 19.2.8 · TypeScript 6.0.3 |
| 모델 | KLUE RoBERTa-base 파인튜닝 · PyTorch · ONNX |
| 브라우저 추론 | ONNX Runtime Web 1.29.0 · WASM · Web Worker |
| 배포 | Vercel — 웹앱 / Cloudflare R2 — 모델 파일 |
| 사례 조회 | Supabase — 현재 제품의 사례 동향 조회 |

사용자가 연락을 분석할 때마다 외부 생성형 AI API를 호출하지 않습니다. 모델 배포 비용과 사용자 기기의 다운로드·연산 부담은 남습니다. 현재 새 분석 결과의 사례 공유는 꺼져 있고 사용자 입력을 학습 데이터로 자동 수집하지 않습니다.

## 개발에 활용한 AI

ChatGPT/Codex는 제품 구현, 회귀 검증, 기록 정리, 문서화에 사용했습니다. 표지는 ChatGPT의 이미지 생성 기능으로 편집했습니다. 사용자의 연락을 분류하는 AI는 별도로 파인튜닝한 RoBERTa 모델입니다. 대화형 AI의 답변을 서비스 판정으로 그대로 쓰지 않습니다.
