# 서비스 소개와 데이터 안내의 화면 설계

[← 제품 소개](../README.md) · [서비스 소개](https://www.phishing-signal.site/) · [신뢰와 데이터](https://www.phishing-signal.site/trust)

처음 방문한 사용자는 서비스가 하는 일과 원문 처리 방식을 살펴볼 수 있어야 합니다. 이미 수상한 연락을 받은 사용자는 바로 입력할 수 있어야 합니다.

2026년 10월 8일 서비스 소개와 데이터 안내를 별도 화면으로 만들었고 10월 10일 첫 진입 화면과 모바일 읽기 흐름을 조정했습니다. 아래 화면 설명은 10월 10일 기준입니다.

## 인트로와 사용 안내의 위치

| 들어온 곳 | 처음 보이는 안내 |
| --- | --- |
| 메인 페이지 `/` | 짧은 브랜드 인트로 뒤에 서비스 소개를 보여줍니다. 본문으로 직접 연결된 링크나 기기의 모션 감소 설정에서는 인트로를 생략합니다. |
| 연락 확인 `/check` | 처음 방문하면 사용 안내를 보여줍니다. 마치거나 건너뛴 기록이 있으면 자동으로 다시 열지 않으며 필요할 때 직접 다시 볼 수 있습니다. |
| 긴급 대응 `/check?screen=incident` | 인트로와 첫 방문 안내를 거치지 않고 대응 화면으로 들어갑니다. |

안내를 마치거나 건너뛴 기록은 브라우저에 저장합니다. 저장소를 지우거나 다른 브라우저로 접속하면 안내가 다시 나타날 수 있습니다. 연락 원문이나 분석 답변을 저장하는 기록은 아닙니다.

## 실제 연락 확인의 흐름으로 소개합니다

소개 화면에서는 같은 합성 연락을 화면에 남기고 스크롤에 따라 위험 신호와 다음 행동이 펼쳐집니다. 아래에서는 세 신호의 뜻과 배송 안내 예시의 행동 확인을 살펴볼 수 있습니다.

이 장면은 **설명용 화면**입니다. 실제 모델을 실행한 결과나 성능 평가 자료로 제시하지 않습니다. 실제 분석은 [연락 확인](https://www.phishing-signal.site/check)에서 이용합니다.

## 신뢰 화면에서 처리 범위를 확인합니다

신뢰 화면의 첫 장면은 어두운 남색 바탕입니다. 연락 원문은 기기 안에 두고 구름에서 내려온 분석 도구가 기기 안으로 들어가도록 표현했습니다. 모델 다운로드와 브라우저 분석의 관계를 한 장면에서 읽을 수 있도록 했습니다. 설명이 끝나면 단계 표시와 진행선은 사라집니다.

아래의 ‘연결과 기록’에서는 네 항목을 골라 읽습니다.

| 항목 | 상세 설명의 소제목 |
| --- | --- |
| 연락과 답변 | 외부 전송 없이 · 보관 방식 |
| 분석 도구 | 파일 준비 · 분석 준비 · 실패 안내와 긴급 대응 |
| 사례와 참여 | 사례 조회 · ‘나도 받았어요’ 참여 |
| 브라우저 기록 | 사용 안내 기록 · 모델 캐시 |

아이콘과 화살표로 먼저 데이터의 이동을 보여줍니다. ‘처리 기준 자세히’를 열면 각 항목의 설명을 읽을 수 있습니다. 접힌 카드의 불필요한 빈 공간을 줄이고 상세 내용은 필요한 만큼 펼쳐집니다. 분석 도구처럼 소제목이 세 개인 항목은 문단 사이 간격을 더 두었습니다.

원문 분석, 모델 다운로드, 사례 조회·참여, 브라우저 저장은 서로 다른 처리입니다. 서비스 이용 통계를 포함한 전체 통신 범위는 [구조 문서](architecture.md#4-네트워크와-개인정보-처리의-범위)에 남겼습니다.

모델의 위험 탐지 한계와 발신자·거래의 안전을 인증하지 않는다는 점도 함께 안내합니다. 이번 변경은 기존 모델이나 임계값, 데이터 수집 정책을 바꾸지 않습니다. [기존 평가 결과와 한계](evaluation.md)는 그대로 유지됩니다.

## 필요한 기능으로 바로 들어갑니다

| 목적 | 화면 |
| --- | --- |
| 서비스의 역할 이해 | [서비스 소개](https://www.phishing-signal.site/) |
| 받은 문자·메시지 확인 | [연락 확인](https://www.phishing-signal.site/check) |
| 원문 처리와 통신 범위 확인 | [신뢰와 데이터](https://www.phishing-signal.site/trust) |
| 공유 사례 살펴보기 | [사례 동향](https://www.phishing-signal.site/trends) |
| 이미 한 행동에 대한 대응 | [긴급 대응](https://www.phishing-signal.site/check?screen=incident) |

기존 `/?screen=incident` 링크도 긴급 대응으로 이어집니다.

## 모바일에서 읽는 순서와 모션

- ‘연결과 기록’의 네 항목은 한 줄로 배치했습니다. 가로로 넘겨 고를 수 있고 스크롤바만 숨겼습니다.
- 상세 설명과 자주 묻는 질문은 소제목, 짧은 문장, 문단 간격으로 읽는 순서를 나눴습니다. 모바일에서 긴 문장이 어색하게 끊기던 부분도 정리했습니다.
- 설명용 예시 화면과 세 가지 신호를 읽는 영역 사이에 여백을 늘렸습니다.
- 항목을 전환하면 아이콘이 한 번 튀어 오르고 화살표가 움직입니다. 마우스를 올렸을 때의 아이콘 반응도 유지했습니다.
- 기기의 모션 감소 설정을 따르며 모션을 사용할 수 없거나 화면 높이가 부족하면 정적 설명을 제공합니다.
- JavaScript 실행 전에도 설명 본문을 읽을 수 있습니다. 본문 바로가기와 키보드 탐색도 지원합니다.

실제 iPhone에서 신호등이 짧고 두껍게 보이고 불빛이 소켓을 벗어나는 제보가 있었습니다. 모바일 신호등의 크기 기준을 화면 높이에서 너비로 바꾸고 렌즈와 본체를 같은 면에서 기울이도록 수정했습니다. 데스크톱에서 화면 너비를 줄여 보는 것만으로 실기기의 렌더링을 확인했다고 판단할 수는 없습니다.

## 확인한 범위

10월 10일 변경은 운영에 반영했습니다. 아래 테스트 수치와 브라우저 확인 기록은 **10월 8일 당시 결과**이며 이후 화면 변경을 다시 검증한 결과가 아닙니다.

<summary>2026년 10월 8일 검증 조건과 결과</summary>

| 확인 대상 | 범위와 결과 |
| --- | --- |
| 관련 코드 회귀 | 단위·렌더링 테스트 110개, 타입 검사와 프로덕션 빌드 통과. 공개 저장소에는 운영 코드와 테스트 파일을 포함하지 않습니다. |
| 작은 화면의 스크롤 장면 | 너비 320·360px × 높이 580·599·600·620·640·641px의 12개 화면 크기. 소개·신뢰 2개 페이지에서 시작·중간·끝·역방향을 포함한 각 5개 시점, 총 120회 검사. |
| 데이터 안내 링크 | 위 12개 화면 크기에서 링크 중심을 실제 좌표로 눌러 본문 이동 확인. |
| 키보드 이동 | 소개·신뢰 2개 페이지에서 같은 해시의 본문 바로가기 실행 후 본문 초점과 다음 Tab 이동 확인. |
| 당시 정적 설명 전환 조건 | 높이 579px 이하, 또는 가로 화면이면서 높이 650px 이하. 모션 감소 설정에서도 정적 설명 제공. 이후 화면 구성의 현재 임계값을 뜻하지 않습니다. |
| 운영 반영 후 확인 | 소개·신뢰·연락 확인·사례 동향·기존 긴급 대응 링크의 정상 응답. 320×600에서 소개·신뢰의 끝 장면과 데이터 본문 링크 확인. 배송 안내 합성 예시의 실제 분석과 ‘모르겠어요’ 선택 후 행동 보류 안내 확인. |

</details>

이 기록은 화면과 탐색을 확인한 결과이며 모델 성능 평가와는 다릅니다. 10월 10일 수정 후 실제 iPhone Safari·Android의 렌더링, 주소창 변화, 터치 관성·프레임률, OS 모션 감소와 확대 글꼴은 후속 확인이 필요합니다. 모든 기기의 품질을 보증하지 않습니다.

공개 문서와 도식을 갱신하면서 앱 테스트·타입 검사·로컬 빌드·브라우저 QA를 새로 실행하지 않았습니다. 기존 평가 수치와 실제 화면 캡처도 재측정한 자료로 바꾸지 않았습니다.
